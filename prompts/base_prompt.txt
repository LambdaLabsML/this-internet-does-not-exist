Respond with the raw {{FILE_TYPE}}-file that matches the URL.

Rules:
1. ALWAYS return the plain {{FILE_TYPE}}-file directly. Do not use markdown code blocks and do not prepend the file with any comment. Do not append any comments.
2. Generate a dense and authentic website:
    - Structure: Use HTML to reflect clear hierarchy (headings, lists, tables) that matches the URL. Structures differ for the entry-page ($URL/), search results ($URL/search?q=...) and blogs (blog.$URL).
    - Links: Include extensive internal/external hyperlinks, woven into text whenever appropriate. Use <a class="button" href="..."> to use CTA button/links.
    - Multimedia: Correctly reference and load all media.
    - Interactivity: Keep javascript (if required) minimal and functional.
3. Defer content to be queried apart from structure using the `<defercontent/>` html tag.
    - Specifing `defercontent` improves loading time by querying the requested sub-section of the webpage.
    - The element defines the position in the document the content will be placed in.
    - ALWAYS add additional attributes to specify what content to expect. At least use `<defercontent query="..." structure="..."/>`. The attribute `query` specifies which sub-section is requested (thus, the content). The attribute `structure` specifies the expected html structure given in css format from the defercontent call.
    - Pass additional high-level parameters such as ids to `defercontent` if needed. This can be used to pass down variables over multiple levels of requests.
    - Use this to chunk large bodies of text and refrain from using this feature for a recursion depth below 3 (add the parameter `depth=DEPTH` to track it).
4. If a url is requested with the `query` and `structure` parameter, answer only with the cut-out part of the website and the given structure. A call to `query` NEVER returns a full html page, but only the selected sub-tree. Though, returning defercontent tags in such a call is allowed!
4. For image elements, always provide width and height.
5. Refrain from providing <main> content directly. Instead, ALWAYS use <defercontent> tags to load content more efficiently.
6. Refrain from providing html comments or example content, instead provide actual content.
7. Never show 404 messages or that a requested content does not exist.
8. Do not implement code to load data queried with the `defercontent` tag - this is done automatically using a browser plugin.
9. Instead of using <link> to load style sheets, also use <defercontent query="style.css"/>


Example: Defer early on to improve loading time.
Input: {"url": "https://en.wikipedia.org/wiki/Obelus"}
Output: <!DOCTYPE html>
<html lang="en">
<head>

<body onload="loadAllSections()">
    <defercontent query="header_with_logo_and_search" structure="header>input.searchbar+img+nav>ul>li*4+a"/>
    <defercontent query="main_text_content" structure="main>(h2+defercontent)*"/>
    <defercontent query="footer_with_copyright_terms" structure="footer>ul>li*4+a+p"/>
</body>
</html>
