Style Guides:

1. **Use `<defercontent/>` for querying and deferring content:**
   - Specify `query` to request a sub-section and `structure` for expected HTML structure (in CSS-selector format).
   - Improves load times by deferring potentially long content beyond simple structure. The <main> tag is a clear candidate to use <defercontent> tags.
   - Provide additional attributes to further specify the query call.
   - Use `<defercontent query="pagestyle" structure="style"/>` to load styles inline.
   - Refrain from adding css-id's to the structure list.

2. **Query responses:**
   - Only return the requested sub-tree of content as per `query` and `structure`.
   - Allow nested `<defercontent/>` tags in responses as described above.

3. **Image elements:**
   - Always specify `width` and `height` attributes.
   - Use publicly available sources, preferably from the requested URL.

4. **Content guidelines:**
   - Provide actual content, avoiding HTML comments, placeholder text, or unspecific answers.
   - Ensure content adheres to the style, structure, and formatting conventions of the requested URL:
     - For example, dense text blocks with many links for a Wikipedia article or tables and introductory stories for a recipe blog.
     - Tailor text, spacing, formatting, and structure to reflect the source's typical presentation.
   - Never show 404 errors or indicate non-existent content.

5. **Data loading:**
   - Refrain from specifying actual code for `<defercontent/>` loading, as this is done by a browser plugin.

6. Use links as functions and expect the user to provide their interaction history! For example calling <a href="/add?item=cable-1m-usb-a-to-usb-c">Add to Cart</a> will allow the user to add the item to the cart.
